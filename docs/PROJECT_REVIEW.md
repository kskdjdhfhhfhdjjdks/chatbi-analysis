# ChatBI 项目理解与本轮优化

## 产品目标与简历对应

目标用户是需要自助取数的业务人员。核心路径是自然语言问数、确认口径、展示数据、继续追问，而非通用聊天。简历强调的双知识库、比率聚合约束、三层安全、MECE 拆解与可观测链路，在仓库里都有对应实现。

本轮按“完善现有模拟数据，做可演示的完整项目”的方向实施，保留数据集和现有页面，不接入真实数据库。

## 代码和数据如何流转

| 模块 | 实际职责 |
| --- | --- |
| `src/pages/ChatBI.tsx` | 会话状态、服务配置探测、模型调用、规则降级、结果与来源展示 |
| `src/engine/llm.ts` | 根据指标/维度目录生成提示词，将模型 JSON 转成校验后的查询计划 |
| `netlify/functions/chat.mjs` | 服务端保存 Key、请求长度限制、进程内限流、DeepSeek 转发、异常处理 |
| `vite.config.ts` | 本地 `/api/chat` 复用线上函数，保持开发与部署入口一致 |
| `src/engine/parser.ts` | 不依赖模型的别名匹配、时间解析、危险输入识别、澄清与追问处理 |
| `src/data/metrics.ts`、`dimensions.ts` | 业务名称、别名、物理字段和指标口径的语义层 |
| `src/engine/pipeline.ts` | 编排查询、校验、计算、图表与归因，生成可展开的 Trace |
| `src/engine/sql.ts` | 生成供审查的 SQL；实际通过内存过滤/分组/聚合计算结果 |
| `src/data/facts.ts` | 确定性生成 202,500 行 SaaS 增长合成数据，模块缓存复用 |
| `src/engine/attribution.ts` | 最近 7 天对紧邻前 7 天的变化检测和维度下钻 |
| `src/engine/mece.ts` | 渠道投放、业务健康、留存提升三类预定义策略分析 |
| `src/engine/suggest.ts` | 按已选指标、维度和分析步骤推荐下一轮问题 |
| `src/data/evals.ts` | 预置评测题、人工标注评分、历史记录；不是在线模型评测器 |

数据范围固定为 2026-03-18 至 2026-09-13，演示时钟固定为 2026-09-14，因此“昨天”始终指向数据末日。每天 5 渠道 × 5 设备 × 5 地区 × 3 套餐 × 3 分层 = 1,125 行，共 180 天；行业字段由确定性散列派生。模拟数据用于复现演示，不代表真实用户行为。

正常问数链路：问题及最近对话 → DeepSeek JSON 查询计划 → 指标、维度、取值、日期和类型校验 → 确定性 SQL 生成及安全校验 → 内存聚合 → 图表和可追溯回答。模型不计算业务数字，不直接执行 SQL。

## 本轮解决的问题

1. **时间被偷换**：原计划校验会把越界日期夹到数据范围内。现在保留绝对日期，范围外返回无数据；拒绝 2 月 30 日、残缺范围、字符串形式的布尔值等畸形输入。
2. **多轮条件丢失**：现在向模型传递上一轮筛选条件、指标、时间、维度与最近对话；规则追问也保留筛选条件。上下文从最近成功的问数取得，闲聊和失败不覆盖它。
3. **模型可能盖过安全判断**：危险问题在调用模型前拦截，编排层再独立检查；即使传入伪造模型计划也不能绕过。SQL 安全校验失败后不执行聚合。
4. **渠道趋势退化为汇总**：原条件令“日期 + 渠道”的执行分支永远不可达。现在真正按日期和渠道聚合，返回多条折线；多序列回答不再把最后一条序列误当整体。
5. **图表和结论误导**：留存率等比率的维度对比使用柱状图；CAC 等人均指标不再把各组数值求和当总体计算占比。
6. **一次失败永久停用**：普通网络或计划错误仅影响当轮，后续可重试；提供重新检测配置入口，逐条标明解析引擎及降级原因。
7. **交互可靠性**：发送加同步锁，避免重复请求；处理中禁用清空与模式切换；异常释放发送状态，兼容中文输入法 Enter。
8. **代理与校验问题**：本地复用函数模块以保留限流状态，限制请求体大小；移除上游错误原文，检查输出截断及消息角色；修正客户端/服务端超时次序。
9. **验证和文档过时**：修复 Windows 上测试 HTTP 服务关闭时的退出崩溃；部署检查允许被忽略的本地配置，并检查真实配置没有被 Git 跟踪。评测页明确静态评分来源。

## 演示时需要准确表达的边界

- 当前已经接上 DeepSeek API 调用链，但没有真实 Key 时只能验证代理及模拟上游契约，不能宣称完成真实模型效果验收。
- SQL 是与计算逻辑对应的展示文本，未连接数据库执行；安全层服务于当前模拟演示，不是数据库权限隔离。
- 普通问数由模型解析；三类策略问题仍由预定义 MECE 模板拆解，界面如实标注来源。结论由计算结果和模板生成，不是第二次模型推理。
- 当前以单指标、日粒度、标准维度筛选为主；预测、任意派生占比、同维度多个值的实体对比与周/月粒度不作为已支持能力。
- DAU/MAU 等去重口径不能仅凭日汇总表还原任意周期去重人数；当前按现有元数据累计计算，不能当真实业务的周期去重用户数。
- 下钻是统计关联定位，不证明业务因果；模拟数据 Android 异常条件覆盖所有渠道，因此不能仅凭下钻路径断言“付费广告停投造成了全部下滑”。
- 比率指标当前下钻贡献度不是严格的分子/分母因子分解；需要正式业务归因时应另建分解算法。
- 进程内限流不跨 Serverless 实例共享。公开部署的模型入口需要结合平台限额和监控控制调用成本。
- 评测页预置的准确率不能写作当前 DeepSeek 的实测准确率；应单独跑真实 Key 下的固定问题集并人工核对计划与结果。

## 验收建议

按 README 的场景逐项运行，查看每条回答来源、实际时间、SQL、数据明细和 Trace。既测能回答的业务问题，也测模糊口径、范围外日期、安全拒绝和模型断连。工程自动验证与模型效果验证是两项不同工作。
